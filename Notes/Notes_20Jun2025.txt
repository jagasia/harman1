Java Collections - Important Interfaces & Classes

1. Core Interfaces
-------------------
- Collection
- List
- Set
- Queue
- Map  (Note: Map is not a subtype of Collection)

2. List Implementations
------------------------
- ArrayList        --> Fast random access, not thread-safe
- LinkedList       --> Good for insert/delete, implements List & Deque
- Vector           --> Legacy, synchronized
- Stack            --> Legacy, LIFO, extends Vector

3. Set Implementations
-----------------------
- HashSet          --> No duplicates, no order
- LinkedHashSet    --> Maintains insertion order
- TreeSet          --> Sorted order, uses TreeMap internally

4. Queue/Deque Implementations
-------------------------------
- PriorityQueue    --> Elements ordered by priority (natural or custom)
- ArrayDeque       --> Faster than Stack/LinkedList for stack/queue ops
- LinkedList       --> Also works as Queue and Deque

5. Map Implementations
-----------------------
- HashMap          --> Key-value pairs, no order, allows 1 null key
- LinkedHashMap    --> Maintains insertion order
- TreeMap          --> Sorted order (by key)
- Hashtable        --> Legacy, synchronized, no null keys/values
- ConcurrentHashMap --> Thread-safe, modern alternative to Hashtable

6. Utility Classes
-------------------
- Collections      --> Static utility methods (sort, reverse, shuffle, etc.)
- Arrays           --> Static methods for array manipulation

7. Comparators
---------------
- Comparable       --> Natural ordering (implements compareTo())
- Comparator       --> Custom ordering (implements compare())

8. Iterators
-------------
- Iterator         --> Universal cursor for Collection
- ListIterator     --> Bidirectional for List
- Enumeration      --> Legacy (for Vector, Hashtable)

What is the difference between Comparable and Comparator?



```
Difference Between Comparable and Comparator in Java
-----------------------------------------------------

1. Purpose
-----------
- Comparable: Used to define natural ordering of objects.
- Comparator: Used to define custom ordering (external control).

2. Interface Location
----------------------
- Comparable: java.lang package
- Comparator: java.util package

3. Method to Implement
-----------------------
- Comparable: int compareTo(Object o)
- Comparator: int compare(Object o1, Object o2)

4. Where to Use
----------------
- Comparable: Implemented by the class itself.
  Example: public class Student implements Comparable<Student>
- Comparator: Separate class or anonymous/lambda, passed during sorting.
  Example: Collections.sort(list, new StudentComparator());

5. Number of Sort Conditions
-----------------------------
- Comparable: Only ONE sort logic can be defined.
- Comparator: MULTIPLE sort logics can be created and passed as needed.

6. Used With
-------------
- Comparable: Collections.sort(list); (uses natural order)
- Comparator: Collections.sort(list, comparator);

7. Example
-----------
Using Comparable (natural order):
----------------------------------
public class Student implements Comparable<Student> {
    int id;
    public int compareTo(Student s) {
        return this.id - s.id;
    }
}

Using Comparator (custom order):
---------------------------------
public class Student {
    int id;
}

public class StudentNameComparator implements Comparator<Student> {
    public int compare(Student s1, Student s2) {
        return s1.name.compareTo(s2.name);
    }
}
Collections.sort(list, new StudentNameComparator());

Or using lambda:
Collections.sort(list, (a, b) -> a.name.compareTo(b.name));

```

| Feature    | Comparable               | Comparator                      |
| ---------- | ------------------------ | ------------------------------- |
| Package    | `java.lang`              | `java.util`                     |
| Method     | `compareTo(Object o)`    | `compare(Object o1, Object o2)` |
| Affects    | Current class            | External/custom class           |
| Sort types | One (natural)            | Many (customizable)             |
| Used with  | `Collections.sort(list)` | `Collections.sort(list, comp)`  |

public class Node<T> {
	T data;
	Node<T> next;
	
	public Node(){}

	public Node(T data, Node<T> next) {
		super();
		this.data = data;
		this.next = next;
	}

	public T getData() {
		return data;
	}

	public void setData(T data) {
		this.data = data;
	}

	public Node<T> getNext() {
		return next;
	}

	public void setNext(Node<T> next) {
		this.next = next;
	}
	
}



public class LinkedList<T> {
	Node<T> start;	

	public LinkedList() {}

	public LinkedList(Node<T> start) {
		super();
		this.start = start;
	}
	
	public void add(T data) {
		Node<T> curr=new Node<>();
		curr.setData(data);
		if(start==null) {
			//adding the first node
			start=curr;
		}else
		{
			//find ref to last node
			Node temp=null;
			for(temp=start;temp.next!=null;temp=temp.next);
			temp.next=curr;
		}
	}
	
	public void traverse() {
		for(Node temp=start;temp!=null;temp=temp.next) {
			System.out.println(temp.getData());
		}
	}
	
}

MultiThreading - Introduction to Thread Pools, Creating a Thread Pool using ExecutorService					


Basically, any program that we execute, becomes a process. 
A microprocessor, allocates resources (time and memory) for each process.


So far, we have created java programs, that run as single threaded process.

a program runs when there is a main method.
So, main method defines the flow of execution.

A process that contains only 1 thread then it is main thread.

We can use multi-threading where main will be the main thread, and other threads will be child threads.

Why we need multi-threading?
	we need multiple simultaneous execution

But we need thread object to start a thread.

Runnable is a functional interface, that contains only 1 abstract method, called "run()" method.



Source code of Runnable interface:



package java.lang;

@FunctionalInterface
public interface Runnable {
    void run();
}




-----------------------
Example for creating threads by implementing Runnable interface.:


class Odd implements Runnable{

	@Override
	public void run() {
		for(int i=1;i<=20;i+=2) {
			System.out.println("Odd: "+i);
			try {
				Thread.sleep(1000);
			} catch (InterruptedException e) {
				// TODO Auto-generated catch block
				e.printStackTrace();
			}
		}
	}
	
}


class Even implements Runnable{

	@Override
	public void run() {
		for(int i=2;i<=20;i+=2) {
			System.out.println("Even: "+i);
			try {
				Thread.sleep(1000);
			} catch (InterruptedException e) {
				// TODO Auto-generated catch block
				e.printStackTrace();
			}
		}
	}
	
}


public class App1 {

	public static void main(String[] args) {
		Thread t1=new Thread(new Odd());
		Thread t2=new Thread(new Even());
		
		t1.start();
		t2.start();
	}

}

what is a thread synchronization?
	synchronized keyword.

a method can be synchronized 
a synchronized block


only when multiple threads try to access a particular object, then synchornization can allow threads 1 by 1

if multiple threads access multiple objects of same class also, there is no synchronization is possible.




synchronized method example:
----------------

public class NumberGenerator {

	public synchronized void display() throws InterruptedException {
		for(int i=0;i<10;i++) {
			System.out.println(Thread.currentThread().getName()+" : " + i);
			Thread.sleep(1000);
		}
	}
}





public class MyThread extends Thread
{
	NumberGenerator ng=null;
	
	public MyThread(NumberGenerator ng) {
		this.ng=ng;
	}
	
	public void run() {
		try {
			ng.display();
		} catch (InterruptedException e) {
			// TODO Auto-generated catch block
			e.printStackTrace();
		}
	}
}




public class AppSync1 {

	public static void main(String[] args) {
		NumberGenerator ng=new NumberGenerator();
		MyThread t1=new MyThread(ng);
		MyThread t2=new MyThread(ng);
		
		t1.setName("Jag");
		t2.setName("Raja");
		
		t1.start();
		t2.start();
	}

}

now, only a portion of the method needs to be synchronized.

we use synchronized block.



public class NumberGenerator {

	public void display() throws InterruptedException {
		String name=Thread.currentThread().getName();
		
		System.out.println(name+" has entered the display method");
		System.out.println(name+" has entered the first for loop");
		for(int i=0;i<10;i++) {			
			System.out.println(name+" : " + i);
			Thread.sleep(1000);
		}
		
		synchronized (this) {
			System.out.println(name+" has entered the sync block");
			for(int i=0;i<10;i++) {				
				System.out.println(name+" : " + i);
				Thread.sleep(1000);
			}
			System.out.println("Last line of sync block by "+name);
		}

		System.out.println(name+" has exited the display method");
	}
}
