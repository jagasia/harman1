Types of Appication contexts:

===============================
Types of ApplicationContext in Spring
===============================

1. ClassPathXmlApplicationContext
-------------------------------
- Loads Spring XML config from the classpath
- Commonly used in standalone apps

Example:
ApplicationContext context = 
    new ClassPathXmlApplicationContext("spring-config.xml");


2. FileSystemXmlApplicationContext
--------------------------------
- Loads Spring XML config from a full file system path
- Used when config is stored outside classpath

Example:
ApplicationContext context = 
    new FileSystemXmlApplicationContext("C:/configs/spring-config.xml");


3. AnnotationConfigApplicationContext
-----------------------------------
- Used with Java-based config using @Configuration and @Bean
- No XML required

Example:
AnnotationConfigApplicationContext context = 
    new AnnotationConfigApplicationContext(AppConfig.class);

// AppConfig.java
@Configuration
public class AppConfig {
    @Bean
    public Calculator calculator() {
        return new Calculator();
    }
}


4. WebApplicationContext
-----------------------
- Used in Spring MVC web applications
- Integrated with ServletContext

Defined in web.xml:

<context-param>
    <param-name>contextConfigLocation</param-name>
    <param-value>/WEB-INF/applicationContext.xml</param-value>
</context-param>

<listener>
    <listener-class>
        org.springframework.web.context.ContextLoaderListener
    </listener-class>
</listener>


5. GenericApplicationContext
--------------------------
- A flexible context that supports both XML and annotation configs
- Allows programmatic registration of beans

Example:
GenericApplicationContext context = new GenericApplicationContext();
XmlBeanDefinitionReader reader = new XmlBeanDefinitionReader(context);
reader.loadBeanDefinitions("classpath:spring-config.xml");
context.refresh();

	2 entities are associated as "has" relationship, but still both can exist independently.	
	for ex:	
		Customer and Product can exist independently
		and still can aggregate to have a relationship

Composition
	2 entities share "has" relationship but 1 controls life of another
	or 1 cannot exist independently.

==============================
Spring Core Annotations
==============================

1. @Component
   - Marks a class as a Spring-managed bean (generic stereotype).

2. @Service
   - Specialized @Component for service-layer beans.

3. @Repository
   - Specialized @Component for DAO classes.
   - Adds exception translation for database errors.

4. @Controller
   - Specialized @Component for Spring MVC controllers.

5. @Configuration
   - Marks a class as a configuration class (replaces XML).

6. @Bean
   - Declares a bean inside a @Configuration class.

7. @Autowired
   - Automatically injects dependent beans by type.

8. @Qualifier("beanName")
   - Helps resolve ambiguity when multiple beans of same type exist.

9. @Value("${property}")
   - Injects values from properties file or hardcoded string.

10. @Scope("singleton"/"prototype")
    - Defines bean scope.

11. @Primary
    - Marks a bean as the default when multiple candidates are available.

12. @Lazy
    - Delays bean initialization until first use.

13. @PostConstruct
    - Method to run **after** bean initialization.

14. @PreDestroy
    - Method to run **before** bean destruction.

15. @DependsOn("beanName")
    - Specifies bean initialization order.

==============================
Spring MVC / REST Annotations
==============================

1. @RestController
   - Combines @Controller + @ResponseBody

2. @RequestMapping("/path")
   - Maps HTTP requests to methods or classes.

3. @GetMapping, @PostMapping, @PutMapping, @DeleteMapping
   - Shortcut annotations for specific HTTP methods.

4. @PathVariable
   - Binds a URI template variable to method argument.

5. @RequestParam
   - Binds a query parameter to method argument.

6. @RequestBody
   - Maps HTTP request body to a Java object.

7. @ResponseBody
   - Returns data (usually JSON) directly in HTTP response.

==============================
Spring Boot Specific
==============================

1. @SpringBootApplication
   - Combines @Configuration, @EnableAutoConfiguration, and @ComponentScan

2. @EnableAutoConfiguration
   - Enables Spring Boot’s auto-configuration mechanism.

3. @ComponentScan
   - Scans packages for @Component and other stereotype annotations.

4. @EnableScheduling
   - Enables Spring’s scheduled task execution (@Scheduled).

What is the purpose of AOP?


Suppose, if you withdraw money from SBI atm 
using ICICI card, still you will be able to get money.

that means, SBI atm software is accessing some methods of ICIC to achieve this.

we are creating some methods, that are accessed by third party.
Now, in order withdraw money, there are some set of functions to be called.

the order of calling the methods to be followed.

We call it as advice.

if you expect third party to follow our advice, then it is doubtful.

So, we allow 3rd party to call our "withdraw" method only. But
before and after and during the method call, there are somethings to be done. We call them as "Advice". that advice will be taken care automatically by a layer called AOP

Which Aspect is to be adviced by which methods.

In an expression, we will specify, those methods matching this expression are all advised by these aspects.
	that expression is called as "Point cut expressions"

Aspect
	contains advices
		before advice or after advice, or around





=======================================
Spring AOP – 3 Main Types of Advice
=======================================

1. @Before Advice
-------------------------
- Runs BEFORE the target method.
- Used for:
    - Logging
    - Security checks
    - Input validation

Syntax:
--------
@Before("execution(* package.Class.method(..))")
public void beforeAdvice(JoinPoint jp) {
    System.out.println("Before method: " + jp.getSignature());
}


2. @AfterReturning Advice
-------------------------
- Runs AFTER method returns successfully.
- Used for:
    - Logging result
    - Post-processing output

Syntax:
--------
@AfterReturning(
    pointcut = "execution(* package.Class.method(..))",
    returning = "result"
)
public void afterReturningAdvice(JoinPoint jp, Object result) {
    System.out.println("Returned value: " + result);
}


3. @Around Advice
-------------------------
- Runs BEFORE and AFTER method.
- You control when the method executes.
- Used for:
    - Performance monitoring
    - Modifying input/output
    - Security

Syntax:
--------
@Around("execution(* package.Class.method(..))")
public Object aroundAdvice(ProceedingJoinPoint pjp) throws Throwable {
    System.out.println("Before method");
    Object result = pjp.proceed(); // calls target method
    System.out.println("After method");
    return result;
}

=======================================
Other (Bonus) Advice Types
=======================================

4. @After
- Runs after method (success or failure)
- Like finally block

5. @AfterThrowing
- Runs only if an exception is thrown
- Used for error logging

=======================================
Example Pointcut Expression
=======================================
execution(* com.example.service.*.*(..))
- *         => any return type
- com.example.service => package
- *         => any class
- *(..)     => any method with any params
